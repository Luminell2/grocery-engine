# Передача проекта: grocery-engine

Бэкенд для вкладки **Shopping** в приложении планирования питания. По блюдам выбранного дня он собирает список продуктов, достаёт **реальные цены** в выбранном магазине, подбирает блюда под бюджет и формирует корзину или ссылку на заказ.

Для США и Канады используется Instacart. Для Европы, Украины и Казахстана — собственные коннекторы к магазинам плюс бесплатный Pepesto для оформления заказа.

Состояние на 08.11.2026: 68 магазинов в 28 странах, 11 тестов проходят, проверка типов чистая.

---

## 1. Запуск за 2 минуты

Нужен Node.js 24 или новее. Внешних зависимостей в рантайме нет; TypeScript нужен только для проверки типов.

```bash
cd grocery-engine
npm install               # только dev: typescript и @types/node
npm start                 # API и демо вкладки на http://localhost:8787
npm test                  # офлайн-тесты
npm run typecheck
npm run smoke -- ah-nl tesco-gb       # живая корзина «понедельника» в выбранных магазинах
node scripts/coverage.ts              # живой прогон по всем магазинам -> data/COVERAGE.md (10–15 мин)
```

Первый запуск скачивает открытые датасеты в `.cache/`: около 10 МБ по Нидерландам и около 45 МБ из Open Prices. Дальше они обновляются раз в сутки.

## 2. С чего читать

| Файл | Что внутри |
|---|---|
| `README.md` | обзор, таблица покрытия, найденные сервисы и цены на них |

| `client/shopping-client.ts` | готовый типизированный клиент (React Native или веб) |

| `src/stores.ts` | реестр магазинов, новый магазин добавляется сюда |

## 3. Как устроено

```
блюда дня -> aggregate() -> список ингредиентов (EN, g/ml/pcs)
          -> словарь EN -> язык магазина (src/ingredients.ts + src/lexicon-extra.ts, 21 язык)
          -> connector.search() -> товары с ценой и фасовкой
          -> matcher: релевантность + самый дешёвый способ покрыть нужное количество
          -> BasketQuote -> compare / plan (бюджет) -> cart (заказ)
```

- `src/connectors/live.ts` — живые API: Mercadona, REWE, Frisco, Сільпо, Wolt.
- `src/connectors/more.ts` — Lidl (18 стран), Rimi, Continente, Prisma, Konzum, Kaufland, сети Великобритании через trolley.co.uk.
- `src/connectors/datasets.ts` — ежедневные датасеты: checkjebon.nl (Нидерланды), heisse-preise.io (BILLA, Австрия).
- `src/connectors/openprices.ts` — Open Prices, цены по чекам покупателей (Франция, Норвегия, Швеция, EDEKA).
- `src/matcher.ts` — релевантность (составные слова, предлоги, стоп-слова).
- `src/planner.ts` — подбор блюд под бюджет с учётом общих упаковок.
- `src/cart.ts` — передача корзины: Instacart, Pepesto, ссылки на товары, текст.
- `src/http.ts` — кэш на 6 часов, склейка одинаковых запросов, не больше 4 одновременных запросов на хост (у Wolt 2), повторы при 429 и 5xx.

**Добавить магазин:** реализовать `StoreConnector` (`info` и `search(query)` → `Offer[]`), добавить его в `src/stores.ts`, проверить через `npm run smoke -- <id>`. Если у магазина новый язык, добавить словарь в `src/lexicon-extra.ts`.

## 4. Надёжность источников

| Тип | Магазины | Насколько доверять |
|---|---|---|
| Живой API или HTML | REWE, Mercadona, Frisco, Сільпо, Continente, Prisma, Rimi, Konzum, Wolt (KZ) | высоко: реальная цена на сегодня |
| Ежедневный датасет | 10 сетей Нидерландов, BILLA | высоко: обновляется раз в сутки |
| Агрегатор | Tesco, Sainsbury's, Asda, Morrisons, Waitrose, Iceland, Co-op (trolley.co.uk) | высоко, но первый запрос медленный, около 2 минут |
| Только акции | Lidl (18 стран), Kaufland (DE, CZ, SK) | частично: онлайн у них только акции недели |
| Цены по чекам | Carrefour, Leclerc, Auchan, Intermarché, Super U и др. (FR); Extra, Kiwi, Rema 1000 (NO); Willys (SE); EDEKA (DE) | оценка с датой; **подбор свежих продуктов слабый**, особенно в NO, SE и DE |

## 5. Известные проблемы

1. **Магазины с ценами по чекам** иногда подставляют переработанный продукт: лимон → печенье с лимоном, яйца → шоколадные яйца в Норвегии. Причина в самих данных: свежей продукции в них мало. Добавлять стоп-слова по одному — бесконечный хвост.
2. **Первый запрос по британским сетям** занимает около 2 минут, потому что открывается много страниц trolley. Нужна ночная предзагрузка цен в базу.
3. **Кэш сейчас только в памяти** и сбрасывается при перезапуске.
4. **Неофициальные API могут измениться** без предупреждения. Симптом — у магазина в `data/COVERAGE.md` резко падает число найденных продуктов или появляются ошибки.
5. **Планировщик не учитывает тип приёма пищи**: может поставить лосося на завтрак.
6. **Словарь** — около 75 ингредиентов. Неизвестные ищутся по-английски; для них есть хук `translate` в `matchIngredient`, туда можно подключить LLM.

## 6. Решения, которые ещё не приняты

| Вопрос | Варианты |
|---|---|
| Что делать со слабыми магазинами с ценами по чекам | понизить их в выдаче с пометкой «оценка» **или** убрать NO, SE и DE из реестра |
| ~25 заблокированных сетей (Migros, Coop CH, Esselunga, Rohlik, Zakaz.ua/Novus, Arbuz.kz и др.) | резидентные прокси (~$3–8 за GB) **или** платный каталог Pepesto (€9.60 за сеть в день) **или** оставить как есть. Пока решено: оставить |
| Живой заказ | нужны `INSTACART_API_KEY` (заявка в Instacart Developer Platform) и `PEPESTO_API_KEY` (кредиты на pepesto.com). Формат запросов проверен тестами, живой вызов — нет |
| Встраивание в приложение | код приложения в этот проект не передавался. Вкладку встраивать по `openapi.yaml` или `client/shopping-client.ts`; `web/index.html` — образец экрана |

## 7. Переменные окружения

| Переменная | Зачем |
|---|---|
| `PORT` | порт API (по умолчанию 8787) |
| `INSTACART_API_KEY`, `INSTACART_ENV=production` | корзина Instacart (без `production` используется dev-сервер) |
| `PEPESTO_API_KEY` | корзина в конкретной европейской сети через Pepesto |
| `GROCERY_CACHE_DIR` | папка для датасетов (по умолчанию `.cache/`) |
| `GROCERY_MAX_PER_HOST` | лимит одновременных запросов на хост (по умолчанию 4) |

## 8. Рекомендуемые следующие шаги

1. База (Postgres или Redis) и ночной прогон популярных ингредиентов по всем магазинам, чтобы ответ приходил мгновенно.
2. Принять решение по магазинам с ценами по чекам (раздел 6).
3. Расширить словарь и подключить LLM-перевод для неизвестных ингредиентов.
4. Выпустить ключи Instacart и Pepesto и проверить живой заказ.
5. Запускать `node scripts/coverage.ts` раз в неделю как мониторинг поломок.

## 9. Юридическое

Неофициальные API и HTML магазинов используются бережно: кэш и ограничение частоты. Open Prices распространяется по лицензии **ODbL**, при показе цен нужна атрибуция «Open Food Facts — Open Prices». Для продакшена в Европе лучше постепенно переходить на партнёрские интеграции: Pepesto, affiliate-программы Wolt и сетей.
